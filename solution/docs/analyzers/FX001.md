# FX001: Member requiring non-null accessed on nullable type

## Cause

You are attempting to access a property or method marked with `[RequiresNotNull]` on a nullable type without using the null-conditional operator (`?.`).

Members marked with `[RequiresNotNull]` throw exceptions (typically `ArgumentNullException`) when accessed with null values. This analyzer provides compile-time safety to prevent runtime exceptions.

## Rule Description

Properties and methods marked with `[RequiresNotNull]` enforce non-null constraints at runtime by throwing exceptions when the underlying value is null. To safely access these members on nullable types, you must use the null-conditional operator (`?.`).

## How to Fix Violations

Use the null-conditional operator (`?.`) when accessing members marked with `[RequiresNotNull]` on nullable types.

### Example of Violation

```csharp
string? nullableStr = GetNullableString();

// ? Error FX001: Cannot access 'Pod' on nullable type 'string?'
nullableStr.Fx.Pod.BuildUriKeyPod(resolver);
```

### Example of Fix

```csharp
string? nullableStr = GetNullableString();

// ? Correct: Using null-conditional operator
nullableStr?.Fx.Pod.BuildUriKeyPod(resolver);
```

## When to Suppress Warnings

**Do not suppress warnings from this rule.** This analyzer prevents runtime exceptions. If you suppress it and the value is null at runtime, you will get an `ArgumentNullException` or similar exception.

If you are certain the value is not null, consider one of these alternatives:

1. **Use a non-nullable type:**
```csharp
string str = GetNonNullableString(); // Declare as non-nullable
str.Fx.Pod.BuildUriKeyPod(resolver);  // No warning
```

2. **Add a null check:**
```csharp
if (nullableStr is not null)
{
    nullableStr.Fx.Pod.BuildUriKeyPod(resolver); // Safe
}
```

3. **Use null-forgiving operator (use with caution):**
```csharp
nullableStr!.Fx.Pod.BuildUriKeyPod(resolver); // Tells compiler you know it's not null
```

## Creating Your Own RequiresNotNull Members

You can use the `[RequiresNotNull]` attribute on your own properties and methods to get the same compile-time safety:

```csharp
using Fuxion;

public static class MyExtensions
{
    [RequiresNotNull]
    public static ValidationExtensions<T> Validate<T>(this T? value) 
        where T : notnull
    {
        ArgumentNullException.ThrowIfNull(value);
        return new ValidationExtensions<T>(value);
    }
}

// Usage:
string? nullable = GetString();
nullable?.Validate().CheckLength(5, 10); // ? Safe with ?.
nullable.Validate().CheckLength(5, 10);  // ? Error FX001
```

## Custom Messages

You can specify a custom error message:

```csharp
[RequiresNotNull(CustomMessage = "Validation extensions require non-null values")]
public static ValidationExtensions<T> Validate<T>(this T? value) 
    where T : notnull
{
    ArgumentNullException.ThrowIfNull(value);
    return new ValidationExtensions<T>(value);
}
```
